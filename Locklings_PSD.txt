Product Overview2.1 Elevator pitchLocklings is a Chrome extension game that turns focused time into power for a squad of collectible elemental creatures. Start an Adventure to block distracting websites, earn FocuPoints for every minute you stay locked in, then spend them at the Dojo to teach your Locklings new moves and take on Distraction Gyms whose leaders are the very habits you are fighting: Notification Nell, Autoplay Al, Doomscroll Dana, FOMO Fiona, and the final boss, The Algorithm.2.2 Mission and design question• Mission: Lower your distractions when you are locked in.• Design question: How can we incentivise you to lock in, and make it fun and rewarding at the end?• Answer in one line: Focus is the only way to make your creatures stronger, and stronger creatures are the only way to beat the bosses that represent your distractions.2.3 Problem• Students and knowledge workers lose long stretches of time to infinite feeds, autoplay, and notifications.• Pure site blockers work, but they feel punitive and are easy to switch off. There is no reason to want to keep them on.• Focus timers with cosmetic rewards (for example growing a tree) are calming, but the reward is passive. There is nothing to do with what you earned.• Gap: no product converts focus into an active, strategic game loop where earned power is immediately usable and fun.2.4 Design pillarsPillarWhat it meansHow it shows up in the MVPFocus is the only faucetThe only source of FocuPoints is completed focus time. Battles never pay FP.FP is earned only in Adventures. Lockboxes give creatures and moves, and only give FP as a duplicate fallback.Commitment with a release valveBlocking is real, but the player can always leave. Leaving costs that session’s reward and nothing more.“Visit site anyway” is always available. It forfeits the current Adventure only. Earned FP, creatures, and moves are never taken away.Readable in five secondsAnyone (including a judge) understands the battle rules instantly.Three elements, one HP value (100) for every creature, one damage formula, one miss chance.Small content, deep feelFewer things, each polished, beats many rough things.9 creatures, 21 moves, 5 gyms, 6 website categories. All hard-coded.Never punish, always nudgeThe game encourages longer, stricter focus through bonuses, never guilt.Tier boundaries and category thresholds are shown as nudges (“Block 1 more to unlock x2.0”).2.5 Core loopStepPlayer actionPlayer feelingSystem1. FocusStarts an Adventure, picks duration and sites to blockCommitment, a little challengeProjects FP, installs block rules, starts timer2. EarnFinishes the AdventurePride, payoff (FP count-up, confetti)Awards locked-in projected FP3. TrainSpends FP at the Dojo on new movesAgency, anticipationValidates element match and price, updates moves4. BattleChallenges the next Distraction GymMastery, tensionTurn-based battle engine with type multipliers and 30% miss5. RewardPicks 1 of 3 LockboxesSurprise, delightRolls creature (1/3) or move (2/3)6. Want moreSees next gym is harderMotivation to focus againNext gym unlocks; stronger moves cost more FP2.6 MVP goals• A player can complete the entire loop (Adventure, earn FP, Dojo, Gym battle, Lockbox) in one sitting during a 3-minute demo, using Demo Mode time scaling.• Website blocking actually works in Chrome during an Adventure, with a branded “Trail Closed” page and a working “Visit site anyway” escape hatch.• Battle math exactly matches Section 7 and is covered by unit tests.• All progress persists locally across browser restarts.2.7 Non-goals for the MVP• No accounts, login, backend server, database, or cloud sync. Everything is local to one Chrome profile.• No multiplayer, PvP, or player-to-player trading.• No mobile app, no app blocking outside the browser, no Firefox or Safari support.• No creature levels, stats (attack, defense, speed), evolutions, or status effects. HP is identical for all creatures and damage depends only on the move and element.• No real-money purchases, ads, or monetization of any kind.• No automatic website categorization. Categories come from a hard-coded catalog (Section 8.4).2.8 Hackathon success criteriaCriterionTargetEnd-to-end demoFull loop shown live in under 3 minutes with zero crashesBlocking worksVisiting a blocked site during an Adventure always shows the Trail Closed pageEngine correctnessAll unit tests in Section 13.1 passPolish momentsAt least 3 “wow” moments: timer ring, FP count-up with confetti, Lockbox revealPitch clarityA judge can explain the game back in one sentence after the demo3. Core Loop and User FlowsEach flow lists the screens (S-numbers refer to Section 10.4) and the state changes that happen. Builders should implement flows exactly in this order.5.1 Flow A: First-time user experience (FTUE)1. Player installs the extension (hackathon: “Load unpacked” from dist/) and clicks the Locklings toolbar icon. A new tab opens index.html.2. S1 Welcome: logo, tagline “Lock in. Level up.”, button “Start”.3. S1 Name: optional Trainer name input (max 16 characters, default “Trainer”). Button “Next”.4. S1 Companion: three cards (Embrit / Fire, Puddlo / Water, Sproutle / Grass), each showing sprite, element badge, description, and its 2 starting moves. Player selects one and clicks “Choose [Name]!”.5. State changes on confirm:a. Create an OwnedCreature for the starter with its defaultMoveIds; set starterId.b. Squad = [starter]. FP = 300 (welcome gift). currentGymLevel = 1. onboarded = true.6. Toast: “Welcome, [Trainer]! Here are 300 FP to get started.” Land on S2 Home.5.2 Flow B: Go on an Adventure (focus session)1. S2 Home: player clicks “Go on an Adventure!”.2. S3 Adventure Setup: choose duration (preset chip or slider) and toggle sites to block, grouped by category. The Points Preview panel updates live.3. Player clicks “Start Adventure”. A confirmation modal shows duration, number of sites, projected FP, and the rule: “Leaving the trail early forfeits this Adventure’s FP.” Buttons: “Lock in!” and “Back”.4. On “Lock in!”, UI sends SESSION_START to the background service worker, which computes FP (Section 7.1), saves activeSession, installs block rules, and schedules the end alarm.5. S4 Adventure Active: big countdown ring, companion animation, projected FP badge. Battle and Dojo are locked.6. Timer reaches 0: background completes the session, removes block rules, adds FP, and shows a system notification.7. S5 Adventure Complete: FP count-up from 0 to the awarded amount with confetti, then CTAs “Let’s Battle!”, “Visit the Dojo”, “Back Home”.5.3 Flow C: Hitting a blocked site1. During an Adventure, player navigates to a blocked domain (for example instagram.com or any subdomain).2. Chrome redirects the tab to blocked.html?site=instagram&d=instagram.com (S6 Trail Closed).3. Page shows the companion, “Trail Closed!”, remaining time, and “You have [X] FP on the line.” Primary button: “Back to my Adventure”. Secondary text link: “Visit site anyway”.4. Back to my Adventure: this tab navigates to index.html#/adventure.5. Visit site anyway: modal “Leave the trail? This Adventure ends now and you will earn 0 FP (you would lose [X] FP).” Buttons: “Stay locked in” (primary) and “Leave the trail” (destructive).6. On “Leave the trail”: page sends SESSION_ABANDON with reason visited_blocked. Background removes ALL block rules, records the session as abandoned with 0 FP, then the page navigates to https://[domain].7. Next time the game tab is focused, it shows the Lost Adventure screen (S5 variant).5.4 Flow D: Battle a Distraction Gym1. S2 Home: “Let’s Battle!” (disabled with lock icon during an Adventure, or if a Lockbox is unclaimed, in which case it routes to the Lockbox screen).2. S7 Gym Map: five gym nodes on a vertical path. The current gym pulses. Player taps it to see the leader card and clicks “Battle!”.3. S8 Battle: intro animation (“Notification Nell wants to battle!”). Each round: player acts, then the enemy acts (Section 7.6).4. Player turn options: Fight (choose a move, and a target if it is a heal), Switch (choose a benched Lockling; uses the turn), Forfeit.5. When a Lockling zones out (0 HP): enemy auto-sends its next creature; player chooses a replacement in a forced-switch modal (does not use a turn).6. Win: “LOCKED IN!” banner, then S9 Lockbox. Loss: S10 Defeat with tips (“Train at the Dojo”, “Try a type advantage”) and a “Rematch” button.5.5 Flow E: Lockbox reward1. On first clear of the current gym, the engine rolls 3 Lockboxes immediately and saves them as pendingReward (refreshing cannot reroll), and currentGymLevel increases by 1.2. S9 Lockbox: three closed boxes. Player clicks one; it shakes for 1 second, then bursts open.3. Creature reveal: “A wild [Name] joined your Lockdex!” Added to Squad automatically if the Squad has fewer than 3 members.4. Move reveal: Move Scroll card. Buttons “Teach now” (pick an eligible creature of the same element; forget-move modal if it already knows 4) or “Save for later” (goes to Move Scroll inventory, teachable for free at the Dojo).5. Spark Pouch reveal: “+250 FP”.6. (P1) The two unchosen boxes flip open to show what they held. Button “Continue” clears pendingReward.5.6 Flow F: Train at the Dojo1. S2 Home: “Training Centre”.2. S11 Dojo: list of owned Locklings. Player selects one.3. Detail view: current moves (max 4) and a list of learnable moves of the same element with prices. Moves held as Move Scrolls show “Free (Scroll)”.4. Player clicks “Teach” on an affordable move. If the creature already knows 4 moves, a forget-move modal appears (the last remaining attack move cannot be forgotten).5. On confirm: FP is deducted (or the Scroll consumed), move added. Success animation: “Embrit learned Blaze Burst!”.5.7 Flow G: Manage Squad1. S2 Home: “Lockdex & Squad”.2. S12 Lockdex: grid of all 9 Locklings (owned in color, unowned as “???” silhouettes).3. Tap an owned Lockling to add it to or remove it from the Squad (max 3, min 1). Up and down arrows reorder; slot 1 is the lead that starts battles.6. CONFIG.DEMO_TIME_SCALE : 1;  const now = Date.now();  const session = { id: crypto.randomUUID(), startedAt: now,    endsAt: now + (input.durationMin * 60_000) / scale, ...input, ...calc,    status: 'active', awardedFp: 0, endedAt: null, isDemo: s.settings.demoMode };  await applyBlockRules(toBlockEntries(input));  await updateState(st => ({ ...st, activeSession: session, lastAdventureSetup: input }));  chrome.alarms.create('session-end', { when: session.endsAt });  return ok(session);} async function completeIfDue() {  const s = await loadState();  if (s.activeSession && Date.now() >= s.activeSession.endsAt) await complete();} async function complete() {                                    // idempotent  const a = (await loadState()).activeSession;  if (!a) return;                                              // already completed  await clearBlockRules();  chrome.alarms.clear('session-end');  await updateState(st => {    if (st.activeSession?.id !== a.id) return st;    const done = { ...a, status: 'completed', awardedFp: a.projectedFp, endedAt: Date.now() };    return { ...st, activeSession: null, fp: st.fp + a.projectedFp, lifetimeFp: st.lifetimeFp + a.projectedFp,      sessionHistory: [done, ...st.sessionHistory].slice(0, CONFIG.HISTORY_MAX),      stats: { ...st.stats, totalFocusMin: st.stats.totalFocusMin + a.durationMin,               adventuresCompleted: st.stats.adventuresCompleted + 1 } };  });  chrome.notifications.create({ type: 'basic', iconUrl: 'icon128.png',    title: 'Adventure complete!', message: '+' + a.projectedFp + ' FP. The feel is cute (squash and stretch, anticipation, a little overshoot) and airy (soft springs, slow easing, low amplitude, things that float rather than snap). Motion is a P0 polish feature: it is the main thing that makes 2D creatures feel alive.10.8.1 Motion principles• Float, don’t snap: default to ease-out curves and soft springs. Nothing moves linearly except the timer ring.• Squash and stretch: every hop squashes on take-off and landing and stretches in the air, keeping volume roughly constant (scaleX goes down when scaleY goes up).• Anticipation: attacks lean back before lunging; Lockboxes wiggle before opening.• Never in sync: creatures on the same screen get a different idle delay so they bob like living things, not a metronome.• Calm screens move least: the Adventure timer uses only slow floats; battles and rewards get the bouncy, punchy motion.• Performance: animate only transform and opacity (plus a brief filter flash). Target 60 fps.10.8.2 Motion tokens (src/app/motion.ts and tailwind.config)TokenValueUseease-airycubic-bezier(0.22, 1, 0.36, 1)Page transitions, fades, HP bar, floatingease-bouncecubic-bezier(0.34, 1.56, 0.64, 1)Pops, button release, badges appearingease-breathecubic-bezier(0.45, 0, 0.55, 1)Idle loops (symmetric in-out)spring-softFramer: { type: spring, stiffness: 180, damping: 20 }Cards, modals, reveal cardsspring-bouncyFramer: { type: spring, stiffness: 320, damping: 14 }Creature hops, selection, Lockbox popdur-micro / short / medium / long150 / 300 / 500 / 900 msHover / transitions / actions / big momentsdur-idle2.8 s (creatures), 3.2 s (Adventure companion)Idle breathing and floating loopsstagger60 msLists and card grids entering10.8.3 The CreatureSprite componentOne component renders every creature everywhere: <CreatureSprite defId uid size state facing />.
